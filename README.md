# MZexperiment — количественная оценка накладных расходов нейросетевой эвристики в A*-LH по сравнению с Weighted A*

Исследовательский проект в рамках курса «Машинное зрение» 

## 1. О чём проект

Классический A* с допустимой эвристикой гарантирует оптимальный путь, но в плотных средах раскрывает слишком много узлов. Обучаемая нейросетевая эвристика (learned heuristic) потенциально сокращает пространство поиска, но требует инференса на каждом раскрытии — и это может оказаться дороже, чем экономия на раскрытиях.

Проект **количественно оценивает компромисс** «время планирования / субоптимальность пути» для:

- Optimal A\ (эвристика Octile, без веса) — эталон оптимальности;
- Weighted A\ (Octile, ε = 1.05) — основной baseline;
- **A\*-LH** (proposed) — A\* с CNN-эвристикой `h_used = max(h_CNN, h_euclidean)`.

Эксперимент проводится на 2D grid-мире 30×30, 8-связная сетка с запретом corner-cutting, плотности 10–50%, single-thread CPU (условие воспроизводимости, **не** симуляция edge-hardware).

**Исследовательский вопрос.** При каких условиях накладные расходы patch-based CNN-эвристики (один патч на раскрытие, single-thread CPU) окупаются сокращением числа раскрытий?

**Главный результат (отрицательный).** В измеренной конфигурации условие окупаемости не выполняется с двух сторон: (1) число раскрытий не сокращается, а растёт; (2) каждое раскрытие дороже за счёт `T_prepare + T_infer + T_other`. Качество путей при этом остаётся близким к оптимальному.

## 3. `experiment.ipynb` — основной эксперимент

**Назначение:** базовый прогон A\* (евклидова эвристика) vs A\*-LH (CNN-эвристика) на всех плотностях, с профилированием времени и сохранением покартных результатов.

**Что делает ноутбук:**

1. **Генерация карт** (по 500 достижимых карт на плотность, лимит 10 000 попыток). Генератор: равномерный шум + кластеры из морфологической дилатации случайных «семян». Старт `(0,0)` и цель `(29,29)` принудительно освобождаются. Карты без пути отбраковываются (BFS, строгая 8-связность). Разделение train/test — **по целым картам**, без утечки патчей.
2. **Обучение единой CNN** (~9.5 тыс. параметров: Conv 2→16→32→16, ядро 3×3, ReLU, GAP, Linear 16→1) на объединённой обучающей выборке. Loss = MSE к `h*` (обратный Дейкстра), Adam, lr = 1e-3, batch = 256, 10 эпох.
3. **Warmup** CNN (3 вызова) перед замерами.
4. **Профилированное тестирование** с 3 повторами на карту и случайным чередованием порядка методов. Для каждой карты сохраняются: `cost_opt` (обратный Дейкстра), время baseline и A\*-LH, число раскрытий, счётчики CNN-вызовов и кэш-хитов.
5. **Сохранение результатов** в `output_data/`.

**Ключевые функции в коде:**

| Функция | Назначение |
|---|---|
| `generate_map` | генерация карты (шум + дилатация семян) |
| `get_neighbors_8way_strict` | 8-связность с запретом corner-cutting |
| `is_reachable_strict` | BFS-проверка достижимости |
| `compute_dijkstra_heuristic_map` | обратный Дейкстра → карта `h*` (для обучения CNN) |
| `dijkstra_optimal` | эталон `L_Optimal` |
| `HeuristicDataset` / `LightweightCNN` | датасет патчей и модель |
| `astar_profiled` | A\* с профилированием (baseline / A\*-LH) |
| `run_experiment` | главный цикл: генерация → обучение → тесты → CSV |
| `analyze_results`, `analyze_mechanism` | статистика и декомпозиция времени |

**Что сохраняется в `output_data/`:**

- `final_results.csv` — покартные результаты (время, раскрытия, стоимость пути, счётчики CNN);
- `cnn_weights.pth` — веса обученной модели;
- `metadata.json` — конфигурация и окружение.

> **Важно:** имена файлов в текущей версии кода — **без** `run_id`. Если запускаешь несколько серий, результаты **перезаписываются**. Для воспроизводимости нескольких серий используй `reproducible_experiment.ipynb` (см. §6), где имена включают `run_id`, а также сохраняются `map_registry` (sha1 карт) и `diagnostics.csv`.

## 4. `experiment2.ipynb` — дополнительный эксперимент

**Назначение:** расширенный прогон с **тремя руками сравнения** и исправленной методологией (включает правки по замечаниям научного руководителя).

**Отличия от `experiment.ipynb`:**

1. **Третья рука — Weighted A\*** (Octile, ε = 1.05) как baseline. В `experiment.ipynb` baseline — евклидова A\*; здесь сравнение ведётся с Weighted A\*, что соответствует заявленной постановке.
2. **Явный структурный элемент дилатации** — `generate_binary_structure(2, 1)` (кросс, 4-связность), 3 итерации, а не дефолтный вызов `binary_dilation`. Это фиксирует форму кластеров и воспроизводимость.
3. **Детерминированное стратифицированное разделение 80/20** (permutation с seed=42) вместо бернуллиевского `rng.random() < 0.8`.
4. **Детерминизм обучения:** `random.seed`, `np.random.seed`, `torch.manual_seed`, `torch.use_deterministic_algorithms(True)`, `DataLoader(num_workers=0, generator=...)`.
5. **Исправленная декомпозиция времени:** `T_total = T_prepare + T_infer + T_heap + T_other + T_path`, где `T_total` **включает** подготовку карт, `T_heap` — только `heappush`/`heappop`, `T_other` — перебор соседей, проверки `g`, запись в словари (не «очередь»).
6. **Возврат пути из `astar_profiled`** и **`validate_path`** по 5 критериям: совпадение концов, смежность шагов, отсутствие коллизий, запрет corner-cutting, совпадение стоимости.
7. **Поправка Бонферрони** для трёх подтверждающих плотностей: `m = 3`, `α_ind = 0.05/3 ≈ 0.0167`, границы 0.833-й / 99.167-й перцентили (покрытие 98.33%).
8. **Диагностика эвристики** (`diagnose_heuristic`): частота завышений `freq_over`, частота занижений, MAE относительно `h*` → `diagnostics.csv`.
9. **Артефакты с `run_id`:** `final_results_<run_id>.csv`, `cnn_weights_<run_id>.pth`, `metadata_<run_id>.json` (с `map_registry` — sha1 карт и split), `diagnostics_<run_id>.csv`.
10. **Автогенерация таблиц** (`build_tables`) из CSV и лога генерации — числа в статье берутся **только** оттуда, без ручного переноса.

**Что сохраняется в `output_data/` (experiment2):**

- `final_results_<run_id>.csv` — покартные результаты с тремя руками, декомпозицией времени и результатами `validate_path`;
- `cnn_weights_<run_id>.pth` — веса;
- `metadata_<run_id>.json` — конфигурация, окружение, `generation_log`, `map_registry`;
- `diagnostics_<run_id>.csv` — `freq_over`, `freq_under`, `mae` по картам.

## 7. Как запустить

### Требования

- Python 3.13+
- PyTorch 2.x
- NumPy, SciPy, tqdm, matplotlib

### Установка

```bash
python -m venv .venv
source .venv/bin/activate        # Linux/macOS
# .venv\Scripts\activate         # Windows
pip install torch numpy scipy tqdm matplotlib jupyter
```

### Запуск

1. Открой `experiment.ipynb` (основной) **или** `reproducible_experiment.ipynb` (воспроизводимая серия) в Jupyter.
2. Выполни все ячейки сверху вниз.
3. Результаты появятся в `output_data/`.

> **Внимание:** `experiment.ipynb` в текущей версии перезаписывает `final_results.csv` при каждом запуске. Для нескольких серий используй `reproducible_experiment.ipynb` (там имена включают `run_id`).

### Время выполнения

Полный прогон на Apple M4 (CPU, один поток): **~30–60 минут** (зависит от числа карт и эпох). Основное время — обучение CNN на десятках тысяч патчей.

## 8. Ограничения

1. **Однопоточный CPU** — условие воспроизводимости, а **не** симуляция edge-hardware (NVIDIA Jetson, R-Car). На реальном edge-железе с аппаратным ускорением инференса числа будут другими.
2. **Генератор** — при плотностях ≥ 40% доля достижимых карт резко падает (23 из 10 000 при 40%, 0 при 50%); это свойство генератора, а не универсальный закон.
3. **Одна обученная сеть** (single run, без валидационного раздела, checkpoint — последняя эпоха). Результат ограничен данной архитектурой и режимом обучения; он **не** доказывает бесперспективность обучаемых эвристик в целом.
4. **Не выполнены абляции:** вклад канала дистанции, операции `max`, подстановка идеальной эвристики (`h = h*`). Это направления будущей работы.
5. **Потенциальные оптимизации** (batched inference, ONNX, CoreML) в данной работе **не измерялись** — это направления будущей проверки, а не доказанные решения.
6. **Механизм роста раскрытий** (завышение vs несогласованность vs ошибка аппроксимации) в данной работе **не разделён**; `diagnostics.csv` даёт частоту завышений и MAE, но не изолирует причину.
